## 1. Shell Architecture
The shell uses a unified responsive container rooted at `DailyEntryShell.tsx`, rendering a `flex-col h-[100dvh] overflow-hidden` wrapper. This cleanly separates the global JKR Context Header and Programme Selection Header, ensuring global navigation authority.

The `SiteDiaryWorkspace.tsx` implements the structural split:
- It mounts within the main contextual boundary.
- Mobile relies on a new standard bottom navigation structure rooted at `pb-safe`.
- Desktop employs a left-side compact navigation rail (`w-20` up to `w-64`).

## 2. Navigation Decisions
### Mobile
A bottom navigation pattern replaces the tab pills to afford thumb-first interactions on phones and to free up the primary content pane entirely. We leverage native `env(safe-area-inset-bottom)` mapped to tailwind's `pb-safe` to avoid collision with iOS indicator lines.

### Desktop
A persistent left navigation rail scales to contextualize the work environment. It sits explicitly underneath the Programme Header to convey its scope (the operational activities are scoped to the Programme).

### Unused Code
The orphaned `BottomNavigation.tsx` (previously flagged in F4-R12) has been safely deleted, verifying the cleanliness of the new model.

## 3. Design Token Decisions (Semantic Layer)
A minimal, reusable semantic token layer was established in `tailwind.config.cjs` to ensure a unified visual language:
- **Surface:** `canvas` (`#09090b`), `primary` (`#18181b`), `raised` (`#27272a`), `interactive` (`#3f3f46`), `border` (`#27272a`), `divider` (`#3f3f46`).
- **Tactical Text:** `primary` (zinc-100), `secondary` (zinc-400), `muted` (zinc-500).
- **Accent:** `operational` (blue-600), `selected` (blue-500).
- **State Indicators:** `valid` (emerald-400), `warning` (amber-400), `destructive` (red-400), `pending` (blue-400).
- **Spacing:** Safe area paddings (`env(safe-area-inset-bottom)`) for modern device compliance.

These tokens replace raw color classes across the shell (`DailyEntryShell.tsx`, `SiteDiaryWorkspace.tsx`), ensuring future packages inherit a consistent vocabulary.

## 4. Truthful Revision Context
The Programme context header was refactored to render the active revision state truthfully based on `revisionState`, rather than unconditionally displaying "Semakan Sah".
- **RESOLVED** + `revisionId`: Shows authoritative `Semakan Sah` (valid state + pulse).
- **RESOLVING**: Displays neutral `Memuatkan Semakan` loading state.
- **UNAVAILABLE**: Displays clear `Tidak Ditemui` non-authoritative state.
- **ERROR**: Displays `Ralat Semakan` error state.
- **IDLE**: Displays neutral `Sedia` state.

## 5. Role-Sensitive Navigation Recon
Exploration was conducted to determine if the `Kelulusan` tab should be conditionally visible based on the authenticated persona's role (e.g. Pegawai Penguasa/Wakil). 
**Limitation/Deferment:** The current frontend `AuthContext` only wraps Supabase's `Session` and `User` object, but does not expose a unified, safe capability/role flag (e.g. `user.canApprove` or `user.role === 'PP'`). As mandated by B01B boundaries, no new RBAC logic was invented on the frontend. The `Kelulusan` tab remains visible to all, deferring role-sensitive hiding to a future capability/RBAC frontend package, relying securely on backend API enforcement (which correctly returns 403 Unauthorized for unauthorized accesses) in the interim.
