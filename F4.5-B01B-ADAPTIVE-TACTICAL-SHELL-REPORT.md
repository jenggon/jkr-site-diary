## 1. Shell architecture

`DailyEntryShell.tsx` owns a `100dvh` adaptive shell. Its global header, Programme context, main workspace, and navigation remain in one bounded layout with independent content scrolling.

`SiteDiaryWorkspace.tsx` provides:

- a thumb-reachable bottom navigation at the mobile breakpoint, including safe-area bottom padding;
- a persistent desktop rail that is compact at `md` and expands at `lg`;
- a wider desktop operational workspace without changing internal workflow ownership.

The obsolete `BottomNavigation.tsx` remains removed.

## 2. Semantic shell layer

The intentionally small semantic Tailwind layer covers canvas/raised/interactive surfaces, tactical text, operational/selected accents, state feedback, and safe-area spacing. It is a shell vocabulary rather than a general-purpose design framework.

## 3. Revision context audit

The Programme context maps lifecycle presentation truthfully:

- `RESOLVED` plus a revision id: authoritative/current valid presentation;
- `RESOLVING`: neutral loading presentation;
- `UNAVAILABLE`: non-authoritative unavailable presentation;
- `ERROR`: error presentation;
- `IDLE`: neutral presentation.

Unresolved and unavailable states do not receive a green/valid authority treatment. No revision lifecycle or domain semantics were changed.

## 4. Approval navigation authority

`AuthContext` still exposes the Supabase session/user rather than a canonical frontend role or capability. B01B therefore does not invent `user.role`, `user.canApprove`, email allowlists, or guessed JWT claims.

`Kelulusan` remains visible. UI visibility is not authorization; backend capability and membership enforcement remain the security authority. Role-sensitive navigation is recorded as UX debt outside this shell package.

## 5. Deterministic real-runtime evidence harness

`scripts/capture-screenshots.ts` now:

- launches an unmodified browser against `http://localhost:3000` (or `B01B_BASE_URL`);
- logs in through the actual UI with seeded synthetic personas;
- selects the real Programme and its current or historical revision;
- requires real localhost GoTrue and application API responses;
- performs semantic assertions before every screenshot;
- fails the process on any required navigation, state, API, or visible-error failure;
- verifies the mobile Records and New Entry images have different SHA-256 hashes.

The previous request interception, fake session, fail-soft interaction handling, redundant selected-nav capture, and mislabeled history capture are removed.

## B01B.1 Micro-Polish Refinement

Authority: HQ approval 2026-08-30. Branch and PR #73 unchanged.

Base for this pass: `f0724f3b03a087c9067774d965547b41897c2d4f`.

### A. Chrome compression (`DailyEntryShell.tsx`)

The Programme/revision context bar moved from a three-row mobile layout (code+Tukar / name / revision stacked) to a two-row layout (code+name on one tight row / revision authority on the second) within a tighter `py-1.5` container (previously `py-3`). On desktop the entire bar remains one inline row. The `flex-col sm:flex-row` strategy eliminates the vertical stacking that consumed excessive mobile height while keeping all authority text permanently visible — no hiding behind responsive classes.

Revision state labels were upgraded from `text-[10px]` to `text-xs` (12 px) so critical operational authority is readable at field distances. The Programme code badge and "Tukar Projek" link were similarly upgraded. Tertiary decorative text ("Sistem Pengurusan Tapak Digital", "Keluar") was left at its existing size per HQ instruction that tertiary chrome must not fight compression.

### B. Selection/status separation (`DiaryManagementList.tsx`)

Both the primary tablist (always visible) and the secondary tablist (detail view) now use `bg-accent-operational` for the selected state on both `Rekod Semasa` and `Semakan Terdahulu`. The prior `bg-amber-700` on `Semakan Terdahulu` selected has been removed.

Historical/superseded semantic meaning is preserved at the record level through the amber card border (`border-amber-800/70 bg-amber-950/20`) and the "Sejarah / Baca Sahaja" amber label on each historical record. SELECTION ≠ STATUS.

The secondary tablist (previously always `bg-zinc-800` for both buttons with no selection state) now carries the same conditional class pattern as the primary tablist.

### C. Tactile navigation states (`SiteDiaryWorkspace.tsx`)

**Desktop rail**: hover upgraded from `hover:bg-surface-primary` (zinc-900 — barely visible on canvas) to `hover:bg-surface-raised` (zinc-800 — clearly distinguished). Active/press state added: `active:bg-surface-interactive` with `active:duration-75` for snappy depression feedback.

**Mobile bottom navigation**: Selected buttons now carry `bg-surface-raised` surface fill plus `border-t-2 border-accent-selected` top-edge indicator — two complementary physicality cues on the button itself, no nested wrappers. Unselected hover gains `hover:bg-surface-primary`. Press feedback: `motion-safe:active:scale-95 active:duration-75`. Icon scale-up on selected is preserved and wrapped in `motion-safe:` for reduced-motion respect.

No decorative container wrappers were added. All physicality comes from surface, edge, and press-depression on the existing button element.

### D. Critical small-text readability

Mobile nav labels upgraded from `text-[10px]` to `text-xs` (12 px) — the most critical single readability fix for field use. Revision state labels and Programme code badge upgraded similarly. Record card "Dikemaskini" timestamp upgraded from `text-[11px]` to `text-xs`. Tertiary chrome left unchanged.
