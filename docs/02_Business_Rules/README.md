# Business Rules Repository

**Version:** 1.0.0
**Project:** JKR Site Diary Platform

## Purpose

This folder contains the official business rules governing the behaviour of the JKR Site Diary Platform.

Business Rules define WHAT the system must do.

Architecture Decision Records (ADR) define WHY the architecture exists.

Implementation defines HOW the business rules are realised.

---

# Hierarchy

The official documentation hierarchy is:

1. Project Constitution
2. Architecture Decision Records (ADR)
3. Business Rules
4. API Specifications
5. Database Design
6. User Interface
7. Source Code

Lower-level documents shall never contradict higher-level documents.

---

# Business Rule Principles

Every Business Rule shall:

- Have a unique identifier.
- Describe one business behaviour only.
- Be implementation independent.
- Be testable.
- Be traceable to architecture decisions.
- Remain stable over time.

---

# Naming Convention

Business Rules use the following identifier format.

BR-001

BR-002

BR-003

...

Identifiers are permanent and shall never be reused.

---

# Document Structure

Every Business Rule shall contain:

- Purpose
- Scope
- Rule
- Rationale
- Exceptions
- Acceptance Criteria
- Related ADR

---

# Ownership

Business Rules are owned by the Product Owner and Architecture Owner.

Implementation teams are responsible for ensuring compliance.
