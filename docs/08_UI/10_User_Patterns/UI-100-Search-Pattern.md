---

# 1. Purpose

Defines a consistent search experience across the JKR Site Diary Platform.

Searching shall always be faster than manual navigation.

---

# 2. Objectives

The Search Pattern shall:

- Reduce navigation time.
- Support large datasets.
- Improve discoverability.
- Maintain operational context.
- Support keyboard-first workflows.

---

# 3. Search Types

- Global Search
- Module Search
- Instant Search
- Advanced Search
- Saved Search

---

# 4. Search Behaviour

Search shall:

- Return results incrementally.
- Support partial matches.
- Support exact matches.
- Highlight matching keywords.
- Preserve filters where appropriate.

---

# 5. Filters

Filters shall support:

- Project
- Date
- Activity
- Status
- User
- Discipline
- Revision

Multiple filters may be combined.

---

# 6. Search States

Idle

Searching

Results

No Results

Offline

Error

---

# 7. Keyboard Support

Ctrl + K

Arrow Keys

Enter

Escape

Tab Navigation

---

# 8. Mobile Behaviour

Search remains accessible using a dedicated search entry point.

Advanced filters shall collapse into an expandable panel.

---

# 9. AI Search

Future AI search may interpret natural language.

Examples:

"Show yesterday concrete work."

"Activities pending approval."

"Photos from Block A."

---

# 10. Accessibility

Search shall support:

Keyboard navigation.

Screen readers.

Visible focus.

Touch interaction.
