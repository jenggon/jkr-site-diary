# 1. Purpose

Defines the standard workspace layout used throughout the JKR Site Diary Platform.

A workspace represents the operational area where users perform tasks while maintaining awareness of project context.

---

# 2. Objectives

The Workspace Pattern shall:

- Maximise usable screen space.
- Maintain operational context.
- Reduce unnecessary navigation.
- Support multitasking.
- Support responsive layouts.

---

# 3. Workspace Structure

A standard workspace consists of:

- Header
- Context Bar
- Main Content
- Supporting Panel
- Action Area
- Status Area

---

# 4. Context Preservation

The workspace shall always display:

- Current Project
- Current Revision
- Current Module
- Current Activity (if applicable)

Users shall never lose awareness of their current working context.

---

# 5. Panel Behaviour

Supporting panels may be:

- Docked
- Collapsed
- Expanded
- Hidden

Panel state should be remembered per user.

---

# 6. Multi-Panel Layout

Desktop workspaces may support:

- Dual Panel
- Triple Panel
- Inspector Panel
- Split View

Users should be able to work without frequent page changes.

---

# 7. Workspace State

The platform should preserve:

- Scroll Position
- Selected Record
- Open Panels
- Active Filters
- Search Query

---

# 8. Mobile Behaviour

Mobile workspaces prioritise:

- Single-column layout
- Bottom Actions
- Expandable panels
- Progressive disclosure

---

# 9. AI Workspace

Future AI capabilities may include:

- AI Summary Panel
- AI Recommendations
- AI Context Awareness

---

# 10. Accessibility

Workspace shall support:

- Keyboard navigation
- Screen readers
- Logical focus order
