# DEV-008 — Definition of Done

## Status

Approved

---

# Purpose

Define the minimum completion criteria before any work item is considered complete.

---

# Objective

Ensure every implementation delivered by the development team meets a consistent quality standard.

---

# Definition of Done

A task is considered DONE only when all applicable criteria below are satisfied.

---

# Specification

Relevant specifications identified.

Architecture verified.

Business Rules satisfied.

No undocumented assumptions.

---

# Implementation

Source code completed.

No placeholder logic.

No TODO left without tracking.

Coding Standards followed.

---

# Quality

Code reviewed.

No critical issues.

Static analysis passes.

Lint passes.

Build passes.

---

# Database

Migration created where applicable.

Rollback verified.

Schema documented.

---

# API

Validation implemented.

Authentication verified.

Authorization verified.

Error responses follow API standards.

---

# UI

Responsive.

Accessible.

Consistent with Design System.

No console errors.

---

# Testing

Unit tests passed.

Integration tests passed.

Manual verification completed.

Regression impact reviewed.

---

# Documentation

Relevant documentation updated.

Related ADR referenced.

Related Product Module referenced.

Changelog updated where required.

---

# Review

Approved by reviewer.

Pull Request merged.
