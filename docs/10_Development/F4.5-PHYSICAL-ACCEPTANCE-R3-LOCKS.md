## PA3-01 — Green is completion/success only

Round 2 physical acceptance still exposed green lines outside meaningful completion/success semantics.

LOCK:
- green is reserved for completed/success semantics only;
- decorative/tactical/progress/header/forecast divider lines must not use green;
- no recurring green underline/rail/accent may appear in the four-fact dashboard merely because a fact is active/current;
- completed Spine nodes and genuine saved/completed success states retain the accepted green treatment;
- this is a recurrence of an already accepted visual principle and is treated as an implementation miss, not a new design preference.

## PA3-02 — PROGRAM KERJA must appear once

The dashboard still exposed duplicated `PROGRAM KERJA` labelling.

LOCK:
- each dashboard fact has exactly one visible label and one value region;
- `PROGRAM KERJA` label appears once only;
- the value region contains only the programme/revision value such as `R03`, never a repeated copy of the label;
- this is a recurrence of an already locked requirement and is treated as an implementation miss.

## PA3-03 — SUMBER hierarchy without nested repetition

LOCK:

- underlying `MULA_DAN_SIAP` lifecycle/domain semantics remain unchanged;

## PA3-07 — Dialog close-control geometry parity

The `×` controls on Completion Seal and VO/APK modal are conceptually accepted but their bounding-box geometry is visually unbalanced.

LOCK:
- close controls use a square bounded box with equal left/right and top/bottom visual padding;
- glyph is optically centred;
- right inset from dialog edge must visually equal the intended top inset and must not create an oversized right-side gap;
- Completion Seal and VO/APK close controls use the same close-control geometry family unless a genuine semantic constraint requires otherwise;
- sharp-sleek geometry remains; no rounded close buttons.

## PA3-08 — Deterministic post-dismiss saved flow

Current behaviour after pressing `×` on the Completion Seal can leave the CATAT surface looking hung/disabled, with no-entry cursor behaviour and only a terminal `Disimpan` state. This is a blocking runtime/product defect.

LOCK:
- pressing `×` dismisses the ceremonial overlay only; it never undoes or mutates the saved record;
- the saved observation remains immutable under existing F4.5 persistence/domain semantics;
- after dismissal, the workspace must settle into an explicit stable **saved receipt state**, not an apparently hung editor;
- saved receipt state must clearly communicate `Disimpan` and retain meaningful next-step actions `Tunjuk Rekod` and `Tambah Aktiviti` at/with the final SIMPAN area;
- do not present disabled form controls with a misleading no-entry interaction affordance as the primary post-dismiss experience;
- `Tambah Aktiviti` is the explicit path to start the next CATAT observation; `×` itself must not silently reset or create a new activity;
- `Tunjuk Rekod` remains the explicit path to the saved/history view;
- no automatic navigation, no automatic scroll-to-top and no timer reset are introduced by dismissal;
- browser proving must exercise save -> Completion Seal -> `×` -> stable saved receipt -> next action availability.

- physical acceptance of live forecast data may use a correctly configured local/server environment; absence of a provider key is a configuration state, not a reason to fabricate weather.
