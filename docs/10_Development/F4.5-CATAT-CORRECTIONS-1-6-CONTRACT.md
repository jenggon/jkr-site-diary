## Product semantic boundary

The four operational workspace destinations are:

- **CATAT** — capture one atomic work observation.
- **AKTIVITI** — continue operational work that remains open.
- **REKOD** — records/history and, in the next slice, the date-level official Site Diary output.
- **SEMAK** — reviewer/approval workspace.

`site_diary_id` remains the exact atomic identity for edit, audit, history and concurrency. This slice does **not** redesign REKOD, daily aggregation, date-level printing, or date-level approval; those are deferred to #7.

## #1 HARIAN — LOCKED

Activity lifecycle authority remains canonical:

`New -> In Progress -> Completed`

A Site Diary row also persists an independent daily observation snapshot:

- `MULA`
- `LAKSANA`
- `SIAP`
- `MULA_DAN_SIAP`

Rules:

- New Activity defaults to `MULA`.
- `MULA` sets Actual Start to the diary date and transitions Activity to In Progress.
- A first system entry that is already ongoing may use `LAKSANA`; Known Start Date is required when Actual Start is not already known.
- `SIAP` requires a known Actual Start and transitions Activity to Completed.
- Same-day start and complete is represented as `MULA_DAN_SIAP`; official print must later mark both Mula and Siap.
- MSP Planned Start is never converted into Actual Start.
- Historical Site Diary work status must not be derived from mutable current Activity status.

## #2 CUACA — LOCKED

Official Site Diary weather is only `ELOK` or `HUJAN`.

Historical evidence:

- hourly source resolution;
- zero or more rain intervals;
- consecutive rainy hourly buckets merge;
- separate rainy periods remain separate;
- zero intervals => `ELOK`;
- one or more intervals => `HUJAN`;
- provider suggestion is assistive; supervisor remains final authority;
- suggestion/provenance is retained when user overrides;
- provider: Visual Crossing Timeline API;
- canonical current project weather point: `3.983583, 101.061639`;
- timezone: `Asia/Kuala_Lumpur`;
- provider key is server-only via `VISUAL_CROSSING_API_KEY`.

Provider responses are cached by site/date. Live forecast and historical evidence are separate semantics. Forecast must never become historical evidence automatically.

## #3 PEKERJA — LOCKED

For a NEW CATAT entry:

- no nine-row pre-population;
- TRE-driven suggested trade chips;
- intelligent trade search/manual fallback;
- one-tap add;
- preserve tactile B / BB / A matrix and live totals;
- WRE recommendation must never auto-assert actual attendance counts.

Continuation keeps prior workforce prefill; edit keeps exact saved workforce.

## #4 HEADER + LIVE WEATHER — PRINCIPALLY LOCKED

Priority header content:

1. Program Kerja / current approved revision;
2. Tinggal;
3. Hari Ke;
4. Semasa;
5. Cuaca live/forecast.

Formula:

- `Hari Ke = current local calendar day - contract start calendar day + 1`.
- `Tinggal = current completion calendar day - current local calendar day`.
- Current authorized finish date drives Tinggal; original finish remains secondary project detail.

Responsive contract:

- desktop: five semantic blocks;
- compact/half-window: preserve readable date/time, no ellipsis;
- mobile: 3 + 2 layout (`Program/Tinggal/Hari Ke`, then `Semasa/Cuaca`).

Live weather is operational awareness only. Show current condition/temperature and the next meaningful rain risk window; expanded/hourly details are secondary.

## #5 NAVIGATION — LOCKED

- wide desktop: labelled sidebar;
- user may collapse it;
- compact/half-window: automatic icon rail;
- temporary expansion overlays content instead of reducing working width;
- mobile: existing four-destination bottom navigation;
- navigation state must never mutate domain/workspace state.

## #6 CATAT + POST-SAVE — LOCKED

Rename `Baharu` to **CATAT**.

Successful save means only: one atomic work observation is persisted.

Post-save behavior:

1. completion acknowledgement (`Kena boh! Ngamsoi.`);
2. soft reset for the next observation;
3. keep the diary date;
4. clear source, location, work times, workforce and notes;
5. weather remains date-level context and may be reused;
6. scroll the workspace to the CATAT start/source picker;
7. focus the source/search entry point where possible.

Remove CATAT post-save actions `Mohon`, `Cetak`, `Aktiviti`, and `Baharu`. Approval and print engines remain intact; their correct date-level handoff is deferred to REKOD #7.
