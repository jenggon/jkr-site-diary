## 2. Read Authority Architecture & Boundary Remediation

### Direct Table SELECT vs RPC Review Boundary
1. **Direct `SELECT` on `public.approval`**: **REVOKED & UNAVAILABLE** (authenticated has no SELECT grant on `public.approval`). Direct table SELECT was intentionally revoked in `a27_atomic_security_hardening.sql`.
2. **Sanctioned Read Boundary**: `f24_get_site_diary_approval_review` (wrapped by `ApprovalReviewReadRepository`), which executes `SECURITY DEFINER` function `private.get_site_diary_approval_review(auth.uid(), p_approval_id)` guarded by capability `SITE_DIARY_APPROVAL_QUEUE_VIEW`.
3. **Suitability**: **SAFE ONLY FOR SITE-DIARY APPROVALS**. The underlying RPC explicitly enforces `IF NOT FOUND OR v_approval.site_diary_id IS NULL THEN RAISE EXCEPTION 'F24_SITE_DIARY_APPROVAL_REVIEW_NOT_FOUND' USING ERRCODE = 'PT404'`.
4. **Generic Semantics Preserved**: Default `approvalRepository` dependency is retained in `ApprovalService` for legacy/non-request flows. When `approvalReviewRepository` is injected via `createApprovalService(accessToken)`, `updateApproval()` routes prerequisite reads through `ApprovalReviewReadRepository.getExact()`.

### Error Mapping
`ApprovalReviewReadRepository` errors are mapped safely within `ApprovalService.updateApproval()`:
- `ApprovalReviewReadError(403)` → `AuthorizationError` (HTTP 403 / `F24_UNAUTHORIZED_CAPABILITY`)
- `ApprovalReviewReadError(404)` → `ApprovalNotFoundError` (HTTP 404)
- `ApprovalReviewReadError(500)` → `InfrastructureError('Failed to retrieve approval record')` (HTTP 500 without leaking raw DB internals/SQLSTATE)
