## 1. Remediation Architecture: Single Request-Scoped Client Composition

The defect confirmed in C09-A recon was that `createSiteDiaryService(accessToken)` passed the authenticated client only to `ResidualAtomicRepository`, while prerequisite repositories (`ProgrammeRepository`, `ProgrammeRevisionRepository`, `ActivityRepository`, and `siteDiaryRepository`) fell back to default anonymous clients. Under C04/C07 RLS policies, direct `SELECT` on these tables is granted only to `authenticated` users who are active Programme members, causing anonymous reads to fail with `42501 permission denied`.

### Solution Implemented
`src/composition/siteDiaryComposition.ts` now instantiates exactly ONE Supabase client per factory call:
- When `accessToken` is provided: `getSupabaseAuthenticatedClient(accessToken)`
- When `accessToken` is omitted: `getSupabaseServerClient()`

A single `SupabaseDatabaseAdapter` bound to this client is injected into:
1. `ProgrammeRepository(adapter)`
2. `ProgrammeRevisionRepository(adapter)`
3. `ActivityRepository(adapter)`

The client is also passed to `createSiteDiaryRepository(client)` and `ResidualAtomicRepository(client)`.

```typescript
export function createSiteDiaryService(accessToken?: string): ISiteDiaryService {
  const client = accessToken
    ? getSupabaseAuthenticatedClient(accessToken)
    : getSupabaseServerClient();
  const adapter = new SupabaseDatabaseAdapter(client);

  return new SiteDiaryService({
    programmeRepository: new ProgrammeRepository(adapter),
    revisionRepository: new ProgrammeRevisionRepository(adapter),
    activityRepository: new ActivityRepository(adapter),
    siteDiaryRepository: createSiteDiaryRepository(client),
    clock,
    logger,
    ...(accessToken ? { atomicRepository: new ResidualAtomicRepository(client) } : {}),
  });
}
```

### Safe Error Redaction & HTTP Mapping
In `src/app/api/site-diary/route.ts` and `src/app/api/site-diary/[siteDiaryId]/route.ts`:
- Known domain errors preserve their intended HTTP status (e.g. 400, 404, 409, 423) and domain error messages.
- `InfrastructureError` and unexpected internal database errors are mapped to HTTP `500` with generic safe messages (`Failed to create site diary`, `Failed to retrieve site diary`, `Failed to update site diary`).
- Raw Postgres errors, SQLSTATE codes (e.g. `42501`), PostgREST traces, and permission denied text are completely redacted.
