## 2. Static Call Graph — C09-A (Site Diary Flow)

### 2.1 Route Entry Point: `POST /api/site-diary` (`src/app/api/site-diary/route.ts`)
1. **Identity Extraction**:
   - Calls `extractVerifiedIdentity(request)` (`src/app/api/_shared/identity.ts`).
   - Extracts `identity.accessToken` (Bearer token) and `identity.actorId` (via `getSupabaseServerClient().auth.getUser(accessToken)`).
   - If missing/invalid, responds `401 Unauthorized`.
2. **Payload Parsing**:
   - Validates JSON body against `createSiteDiarySchema` (validating `programme_id`, `revision_id`, `activity_id`, `activity_date`, `operation_intent`, `notes`, etc.).
3. **Service Construction**:
   - Calls `createSiteDiaryService(identity.accessToken)` (`src/composition/siteDiaryComposition.ts`).
   - Instantiates `SiteDiaryService` with dependencies:
     - `programmeRepository`: `new ProgrammeRepository()`
     - `revisionRepository`: `new ProgrammeRevisionRepository()`
     - `siteDiaryRepository`: singleton `siteDiaryRepository`
     - `clock`: `new SystemClock()`
     - `logger`: `new Logger({ module: 'SiteDiaryService' })`
     - `atomicRepository`: `new ResidualAtomicRepository(getSupabaseAuthenticatedClient(accessToken))`
     - `activityRepository`: (defaults inside `SiteDiaryService` constructor to `new ActivityRepository()`)

### 2.2 Execution Flow: `SiteDiaryService.createSiteDiary(cmd)` (`src/services/siteDiaryService.ts`)
1. **Prerequisite Read 1 — Programme Validation**:
   - Calls `this.programmeRepo.findById(cmd.programmeId)`.
   - Client: `SupabaseDatabaseAdapter` -> `getSupabaseServerClient()` (**UNAUTHENTICATED / ANON**).
   - Target Table: `public.programme`.
   - Security Policy: Under C04 (`20260823100000_f2_7_c04_programme_discovery_authorization.sql`), `REVOKE ALL ON TABLE "public"."programme" FROM anon, authenticated; GRANT SELECT TO authenticated; POLICY "c04_active_programme_membership_select" USING ("private"."is_programme_member"("programme_id"))`.
   - Effect: Anon client query fails (permission denied / 0 rows returned), returning `ProgrammeNotFoundError` or `InfrastructureError`.
2. **Prerequisite Read 2 — Activity Validation**:
   - Calls `this.activityRepo.findById(cmd.activityId)`.
   - Client: `SupabaseDatabaseAdapter` -> `getSupabaseServerClient()` (**UNAUTHENTICATED / ANON**).
   - Target Table: `public.activity`.
   - Security Policy: Under C07 (`20260823110000_f2_7_c07_dependent_programme_read_authority.sql`), `REVOKE ALL ON TABLE "public"."activity" FROM anon, authenticated; GRANT SELECT TO authenticated; POLICY "c07_programme_member_select_activity" USING ("private"."is_programme_member"("programme_id"))`.
3. **Prerequisite Read 3 — Programme Revision Validation**:
   - Calls `this.revisionRepo.findById(cmd.revisionId)`.
   - Client: `SupabaseDatabaseAdapter` -> `getSupabaseServerClient()` (**UNAUTHENTICATED / ANON**).
   - Target Table: `public.programme_revision` (and internal call to `public.programme` for `current_revision_id`).
   - Security Policy: Under C07 (`20260823110000_f2_7_c07_dependent_programme_read_authority.sql`), `REVOKE ALL ON TABLE "public"."programme_revision" FROM anon, authenticated; GRANT SELECT TO authenticated; POLICY "c07_programme_member_select_programme_revision" USING ("private"."is_programme_member"("programme_id"))`.
4. **Final Atomic Mutation**:
   - Calls `this.atomicRepo.createSiteDiary(createPayload, cmd.submittedBy)` -> calls RPC `f1_create_site_diary_full_atomic`.
   - Client: `ResidualAtomicRepository` instantiated with `getSupabaseAuthenticatedClient(accessToken)` (**AUTHENTICATED / REQUEST-SCOPED**).

## 3. Static Call Graph — C09-B (Approval Flow)

### 3.1 Route Entry Points:
- `POST /api/approval` (`src/app/api/approval/route.ts`)
- `PATCH /api/approval/[approvalId]` (`src/app/api/approval/[approvalId]/route.ts`)
- `GET /api/approval/[approvalId]` (`src/app/api/approval/[approvalId]/route.ts`)

1. **Identity Extraction**:
   - Calls `extractVerifiedIdentity(request)` (`src/app/api/_shared/identity.ts`).
   - Extracts `identity.accessToken` and `identity.actorId`.
2. **Service Construction**:
   - Calls `createApprovalService(identity.accessToken)` (`src/composition/approvalComposition.ts`).
   - Note: In `approvalComposition.ts`, dependencies are created as module-level singletons:
     - `const revisionRepository = new ProgrammeRevisionRepository()` (**UNAUTHENTICATED / ANON**)
     - `const activityRepository = new ActivityRepository()` (**UNAUTHENTICATED / ANON**)
     - `siteDiaryRepository` (**UNAUTHENTICATED / ANON**)
     - `progressRepository` (**UNAUTHENTICATED / ANON**)
     - `approvalRepository` (**UNAUTHENTICATED / ANON**)
     - `atomicRepository: new ApprovalAtomicRepository(client)` where `client` is `accessToken ? getSupabaseAuthenticatedClient(accessToken) : getSupabaseServerClient()` (**AUTHENTICATED / REQUEST-SCOPED**).

### 3.2 Execution Flow: `ApprovalService.createApproval(cmd)` (`src/services/approvalService.ts`)
1. **Prerequisite Reads in `validateContext(cmd)`**:
   - **Read 1 — Programme Revision**: `this.revisionRepo.findById(cmd.revision_id)`
     - Repository: `ProgrammeRevisionRepository` -> `SupabaseDatabaseAdapter` -> `getSupabaseServerClient()` (**UNAUTHENTICATED / ANON**).
     - Target Table: `public.programme_revision` (C07 RLS / revoked from anon).
   - **Read 2 — Activity**: `this.activityRepo.findById(cmd.activity_id)`
     - Repository: `ActivityRepository` -> `SupabaseDatabaseAdapter` -> `getSupabaseServerClient()` (**UNAUTHENTICATED / ANON**).
     - Target Table: `public.activity` (C07 RLS / revoked from anon).
   - **Read 3 — Site Diary** (if `site_diary_id` provided): `this.siteDiaryRepo.getSiteDiaryById(cmd.site_diary_id)`
     - Repository: `siteDiaryRepository` -> `supabase` (`getSupabaseBrowserClient()`) (**UNAUTHENTICATED / ANON**).
     - Target Table: `public.site_diary` (C07 RLS / revoked from anon).
   - **Read 4 — Progress** (if `progress_id` provided): `this.progressRepo.getProgressById(cmd.progress_id)`
     - Repository: `progressRepository` -> `supabase` (`getSupabaseBrowserClient()`) (**UNAUTHENTICATED / ANON**).
     - Target Table: `public.progress`.
2. **Final Atomic Mutation**:
   - Calls `this.atomicRepo.create(payload, cmd.requested_by, cmd.expected_site_diary_last_modified_at)` -> calls RPC `a27_create_approval_atomic`.
   - Client: `ApprovalAtomicRepository` with `getSupabaseAuthenticatedClient(accessToken)` (**AUTHENTICATED / REQUEST-SCOPED**).

### 3.3 Execution Flow: `ApprovalService.updateApproval(approvalId, cmd)` (`src/services/approvalService.ts`)
1. **Prerequisite Read 1 — Existing Approval**: `this.approvalRepo.getApprovalById(approvalId)`
   - Repository: `approvalRepository` -> `supabase` (`getSupabaseBrowserClient()`) (**UNAUTHENTICATED / ANON**).
   - Target Table: `public.approval`.
2. **Prerequisite Read 2 — `validateContext(...)`**:
   - Executes the 4 unauthenticated prerequisite reads via `revisionRepo`, `activityRepo`, `siteDiaryRepo`, `progressRepo` (**UNAUTHENTICATED / ANON**).
3. **Final Atomic Mutation**:
   - Calls `this.atomicRepo.update(approvalId, payload, cmd.approved_by, cmd.expected_site_diary_last_modified_at)` -> calls RPC `a27_update_approval_atomic`.
   - Client: `ApprovalAtomicRepository` with `getSupabaseAuthenticatedClient(accessToken)` (**AUTHENTICATED / REQUEST-SCOPED**).
