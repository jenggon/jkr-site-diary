# F2.7-C09-A: Site Diary Authenticated Prerequisite Read Context Recon

## Classification: CONFIRMED

The hypothesis is **CONFIRMED**:
1. Real HTTP `POST /api/site-diary` successfully authenticated caller P1 and reached `SiteDiaryService.createSiteDiary`.
2. Execution failed on the very first prerequisite read (`ProgrammeRepository.findById`) with `Database error [42501]: permission denied for table programme` because `createSiteDiaryService` instantiated prerequisite repositories using default unauthenticated anonymous clients rather than request-scoped authenticated clients.
3. Direct control read using the exact same P1 JWT Bearer token against `programme` (as well as `activity` and `programme_revision`) succeeded with HTTP `200` OK and returned valid data under RLS policy `c04_active_programme_membership_select`.
4. Exactly zero (`0`) rows were created in `site_diary`.

---

## 1. Trace Analysis (Route → Service → Repository)

### Endpoint Boundary (`src/app/api/site-diary/route.ts`)
- Extracts verified caller identity via `extractVerifiedIdentity(request)`: `identity.accessToken`, `identity.actorId`.
- Calls `createSiteDiaryService(identity.accessToken)`.

### Composition Boundary (`src/composition/siteDiaryComposition.ts`)
- `createSiteDiaryService(accessToken)` instantiates:
  - `programmeRepository: new ProgrammeRepository()` (uses default anonymous `SupabaseDatabaseAdapter`)
  - `revisionRepository: new ProgrammeRevisionRepository()` (uses default anonymous `SupabaseDatabaseAdapter`)
  - `siteDiaryRepository: siteDiaryRepository` (uses default anonymous singleton)
  - `activityRepository` omitted (defaults inside `SiteDiaryService` constructor to `new ActivityRepository()`, which uses default anonymous `SupabaseDatabaseAdapter`)
  - `atomicRepository: new ResidualAtomicRepository(getSupabaseAuthenticatedClient(accessToken))` (the ONLY request-scoped authenticated dependency).

### Service Execution Boundary (`src/services/siteDiaryService.ts:createSiteDiary`)
- **Step 1 (Prerequisite Read 1)**: `this.programmeRepo.findById(cmd.programmeId)`
  - Calls `adapter.selectOne('programme', { programme_id: id })` via anonymous client.
  - Supabase returns PostgREST error `42501` (`permission denied for table programme`).
  - Adapter wraps into `InfrastructureError("Database error [42501]: permission denied for table programme")`.
  - Service returns `Failure(InfrastructureError)`.
  - Route maps Failure to HTTP `400` with body: `{"error": "Database error [42501]: permission denied for table programme"}`.
- **Subsequent Prerequisite Reads (Activity, Revision)**:
  - Both `ActivityRepository` and `ProgrammeRevisionRepository` also use default anonymous adapters and would fail similarly with `42501` if reached.
- **Mutation Boundary**:
  - `this.atomicRepo.createSiteDiary(...)` is never reached.
